# PaddleOCR PP-DocLayoutV3 + PP-OCRv6

## What this runs

Three-stage document OCR on Cloud AI 100:

| Stage | Model | Input | Output |
|---|---|---|---|
| Layout | PP-DocLayoutV3 | Document image | Regions with label, class_id, score, box |
| Detection | PP-OCRv6 | Region crops | Text line boxes |
| Recognition | PP-OCRv6 | Line crops 48×1536 | Decoded text + confidence |

All stages run on Cloud AI 100 via QPC.

## Quick start

Environment:

```bash
python3.12 -m venv env_paddle
source env_paddle/bin/activate
pip install --upgrade pip
# Export/compile extra
pip install -e '/path/to/cloud-ai-sdk-root[paddle-ocr]'
# Runtime only
pip install -e '/path/to/cloud-ai-sdk-root[paddle-ocr-infer]'
```

SDK/device checks:

```bash
python -c "import onnx, onnxruntime, cv2, PIL"
 /opt/qti-aic/tools/qaic-util -q
```


Export and compile:

```bash
python -m qaic_models.vision.ocr.paddle_ocr.export --work-dir build/paddle_ocr
```

Export downloads the stage models from Hugging Face (layout: `PaddlePaddle/PP-DocLayoutV3_safetensors`; det: `PaddlePaddle/PP-OCRv6_medium_det_onnx`; rec: `PaddlePaddle/PP-OCRv6_medium_rec_onnx`) into `--work-dir`, writes the deployable ONNX artifacts, and compiles the QPCs (layout latency, det latency, rec latency, and the batch-2 rec throughput build).

Flags:

- `--layout` / `--det` / `--rec` — export and compile only that stage (default: all three).
- `--skip-onnx` — reuse the deployable ONNX already under `--work-dir`; the QPC compiles still run. Only reuse artifacts generated by the current export code and flags — delete them to force a fresh export.
- `--det-image` / `--rec-image` — sample images used to generate the golden reference tensors. The recipe ships no images; when omitted, the defaults are downloaded at export time from the arXiv source of the validated white-paper page (arXiv:1212.1442v1): page 1 rendered at 144 DPI feeds layout/detection, and its PACS-numbers line (a clean single text line) feeds recognition. Both are written under `--work-dir/samples/` and reused on later runs.
- `--det-hf-repo` / `--rec-hf-repo` (or `--hf-repo` for both) — override the det/rec source repositories.
- `--out-masks` — retain PP-DocLayoutV3's optional `out_masks` layout output (off by default).

To regenerate a stale `--work-dir`, delete it and rerun; with `--skip-onnx`, keep the ONNX and recompile only the QPCs.

Generated files under `--work-dir`.

Required at runtime (QAIC) — the stage predictors resolve these from the `--model` directory:

```
char_dict.txt
qpc_layout_latency/
qpc_det_latency/
qpc_rec_throughput/
```

Compile inputs and extras (not needed to run the QPCs): the deployable ONNX files and the layout precision file the QPCs were compiled from (`pp-doclayoutv3_704_fp16ready.onnx`, `pp-doclayoutv3_fp32_cross_attention.yaml`, `pp-ocrv6-medium-det-onnx_fp16ready.onnx`, `pp-ocrv6-medium-rec-onnx_fp16ready.onnx` — kept so `--skip-onnx` can recompile the QPCs without re-exporting), an extra 16-core rec latency build (`qpc_rec_latency/`, for benchmarking), the raw stage ONNX, `.raw` reference tensors, and `fp16_sensitivity.json` (see the export output for the full list).

Pass the work directory to `--model`.

## Python API

Each independently usable PaddleOCR stage exposes a local `Model` alias. The
stage inputs are intentionally different: layout and detection accept image
paths, while recognition accepts BGR line-crop arrays.

Each stage facade owns one backend/session and serializes concurrent
`predict` calls to that backend. The standalone detector returns coordinates
relative to its supplied image/crop; the full pipeline offsets them to document
coordinates.

```python
import cv2

from qaic_models.vision.ocr.paddle_ocr.layout import Model as LayoutModel
from qaic_models.vision.ocr.paddle_ocr.detection import Model as DetectionModel
from qaic_models.vision.ocr.paddle_ocr.recognition import Model as RecognitionModel
from qaic_models.vision.ocr.paddle_ocr.preprocess import crop_box

layout = LayoutModel("build/paddle_ocr", provider="QAicExecutionProvider", device_id=0)
det = DetectionModel("build/paddle_ocr", provider="QAicExecutionProvider", device_id=1)
rec = RecognitionModel("build/paddle_ocr", provider="QAicExecutionProvider", device_id=2)

regions = layout.predict("document.png")["prediction"]
region_path = "region.png"                 # a crop written by the caller
det_result = det.predict(region_path)
line_crops = [cv2.imread("line.png")]       # BGR line crops prepared by the caller
rec_result = rec.predict(line_crops)
```

Full pipeline:

```python
from qaic_models.vision.ocr.paddle_ocr import Pipeline

pipeline = Pipeline(
    "build/paddle_ocr",
    provider="QAicExecutionProvider",
    layout_device_id=0,
    det_devices=(1, 2),
    rec_device_id=3,
    rec_sessions=4,
)
result = pipeline.predict("document.png")
for entry in result["prediction"]["texts"]:
    print(f"{entry['confidence']:.4f} {entry['text']}")
```

PaddleOCR pipeline result schema (specific to this pipeline, not a package-wide
contract): `{"prediction": {"texts": [...], "regions": [...]}, "latency_ms": float}`.

## Input and output details

Preprocessing: layout 704×704, det 640×640 letterbox, rec 48×1536 resize with right-pad.

Result fields: `texts` = [{text, confidence, box, layout}], `regions` = [{box, label, class_id, score, order}]. Text `box` is `[x0, y0, x1, y1, det_score]` in original image coordinates — five values, the last being the detector box score; `layout` carries the parent region's {box, label, class_id, score, order}. Region `box` is `[x0, y0, x1, y1]`. Texts are emitted in document reading order. Non-text layout regions (e.g. images, tables, charts, formulas) produce placeholder text entries with `status: "layout_placeholder"`, bracketed label text such as `"[image]"`, `confidence: 0.0`, and the region's `layout` metadata.

## Triton serving

Generate Triton repo:

```bash
python -m qaic_models.vision.ocr.paddle_ocr.export \
  --work-dir build/paddle_ocr \
  --triton-model-repo build/paddle_ocr/triton-model-repo
```

Start server. The conventional placeholder `--mount type=bind,source=</path/to/cloud-ai-sdk root>,target=/cloud-ai-sdk` is not shell-safe as written (the angle brackets and space are shell metacharacters), so the command below uses a metacharacter-free path instead: replace `/path/to/cloud-ai-sdk` with the absolute path to this repository, and if that path contains spaces quote the whole `--mount` value:

```bash
docker run -it --rm --shm-size=4g --network host \
  --mount type=bind,source=/path/to/cloud-ai-sdk,target=/cloud-ai-sdk \
  --device /dev/accel/ \
  ghcr.io/qualcomm/cloud_ai_triton_server:1.23.2.0 \
  bash -lc 'pip3 install "/cloud-ai-sdk[paddle-ocr-infer,triton]" && \
    /opt/tritonserver/bin/tritonserver --model-repository=/cloud-ai-sdk/qaic_models/vision/ocr/paddle_ocr/build/paddle_ocr/triton-model-repo'
```

Model I/O. `H,W` are dynamic per request; the STRING outputs carry the JSON payloads shown:

| Model | Input | Output |
|---|---|---|
| paddle_ocr_layout | src UINT8 [H,W,3] (raw BGR image) | regions STRING [1] — `{"regions": [{"box": [x0, y0, x1, y1], "label": ..., "class_id": ..., "score": ..., "order": ...}, ...]}` in original-image coordinates, reading order; region_count INT32 [1] |
| paddle_ocr_det_qpc | src UINT8 [H,W,3] (raw BGR region crop) | boxes STRING [1] — `{"boxes": [[x0, y0, x1, y1, score], ...]}` in region-crop coordinates (offset by the region origin for image coordinates); box_count INT32 [1] |
| paddle_ocr_rec | x FP32 [1,3,48,1536] (one prepared line; the leading 1 is the batch dim) | text STRING [1] (decoded line), confidence FP32 [1]; requests batch up to 2 lines per QPC pass |

Client flow: layout → det → rec.

```bash
python demo_triton.py --image document.png
```

The client uses `tritonclient.http`. Flags: `--image`, `--server-url` (default `localhost:8000`), `--concurrency` (default 8). Run from `qaic_models/vision/ocr/paddle_ocr`, as with `demo_pages.py`.

## Troubleshooting

- No Ready device: check `qaic-util -q`.
- Missing `programqpc.bin`: re-run export, ensure `--model` points to build dir.
- Triton load failure: run in-container `pip3 install "/cloud-ai-sdk[paddle-ocr-infer,triton]"`.
- QID allocation errors: pipeline needs QID 0 layout, QID 1,2 det, QID 3 rec.
